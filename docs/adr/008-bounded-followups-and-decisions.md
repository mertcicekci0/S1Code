# Bounded native follow-ups and focused decisions

A coding task often needs a second user request after inspection. The native engine
now accepts that request in its existing terminal conversation. Exact previous
user requests remain pinned context, and canonical events/artifacts stay in the same
store. The new request invalidates pending proposals and verification. It does not
rerun unknown effects or reset usage. Interactive submission explicitly grants the
displayed additional bounded request allowance; waiting for input consumes no
provider requests or execution latency. Headless follow-ups keep cumulative caps.

Jev relevance selection receives candidate IDs, exact hashes/preconditions, compact
action metadata and useful partial evidence/code excerpts. Full arguments remain in
the runtime. Byte limits can remove explicitly marked excerpts, never user requests
or candidate identities. Insufficient evidence has an explicit generation escape.
The constrained generative baseline still receives full candidate arguments because
its contract returns the exact action rather than an ID; reports must retain this
wire-format difference instead of claiming identical prompt sizes.

Compaction happens before generation, not before every deterministic local tool.
The runtime first checks whether any valid eviction plan can fit. It does not call
a model for impossible pinned budgets or tiny independent outputs that cannot save
space. Eligible call/dependency groups stay together. Independent retention questions
are batched up to eight, with batch size reduced until both actual serialized byte
estimates fit configured limits. Batches stop once the selected group closure meets
the lower working-set target. Canonical artifacts are never deleted.

Patch capture depends on source evidence for the changed files, not all nearby
commands. This prevents unrelated history becoming permanently pinned. Provenance
remains in candidate/events independently of the context dependency graph.

Metrics now record serialized decision request/state bytes including retries.
These are not tokens, cost or a speed measurement. Old sessions without complete
byte accounting retain unknown values. Cache hits do not count as HTTP requests,
and cancellation is checked even before returning a cache hit.

Nested patch creation keeps the existing whole-patch validation/approval boundary.
Missing allowed parents are recorded as they are created. Recovery accepts old file
journals, restores file contents, and removes only recorded empty directories. A
crash between directory creation and its journal update can leave an empty directory;
no multi-file or file-plus-directory atomicity is claimed. User-created contents
prevent directory removal. Policy version 3 rejects earlier pending approvals.
